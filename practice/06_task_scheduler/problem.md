# 06. 우선순위 태스크 스케줄러 (선점형)

단일 코어 RTOS의 **선점형 우선순위 스케줄러**를 시뮬레이션하세요.

태스크 `i`는 `(도착 시각 a_i, 우선순위 p_i, 실행 시간 e_i)`를 가집니다.
- 시간은 1틱 단위로 흐릅니다. 매 틱마다 CPU는 태스크 하나를 1틱만큼 실행합니다.
- 각 틱이 시작될 때, **도착했지만 끝나지 않은** 태스크 중 다음 순서로 하나를 고릅니다.
  1. 우선순위 숫자가 **작을수록** 높은 우선순위
  2. 우선순위가 같으면 **도착 시각이 빠른** 태스크
  3. 그것도 같으면 **번호가 작은** 태스크
- 더 높은 우선순위 태스크가 도착하면 실행 중인 태스크는 즉시 선점됩니다.
- 실행할 태스크가 없으면 CPU는 idle 상태로 1틱을 보냅니다.

모든 태스크의 **완료 시각**(마지막 틱이 끝난 시각)을 번호 순서대로 출력하고,
마지막 줄에 **문맥 교환(context switch) 횟수**를 출력하세요.
문맥 교환은 "직전 틱에 실행한 태스크와 다른 태스크를 실행할 때" 1회로 셉니다.
idle 틱은 태스크로 치지 않으며, idle 이후 처음 실행하는 태스크가
idle 직전에 실행한 태스크와 다르면 1회로 셉니다. 맨 처음 실행은 세지 않습니다.

## 입력
```
N                 (1 ≤ N ≤ 100,000)
a_1 p_1 e_1       (0 ≤ a_i ≤ 10^9, 0 ≤ p_i ≤ 255, 1 ≤ e_i ≤ 10^4)
...
```

## 출력
```
완료시각_1
...
완료시각_N
문맥교환 횟수
```

## 예시 입력
```
3
0 5 4
1 1 2
2 3 1
```

## 예시 출력
```
7
3
4
3
```

설명:
```
틱 [0,1)  T1 실행 (남은 3)
틱 [1,2)  T2 도착(우선순위 1) → T1 선점, T2 실행       switch 1
틱 [2,3)  T3 도착(우선순위 3), T2 계속 실행 → T2 완료 (시각 3)
틱 [3,4)  T3(3) vs T1(5) → T3 실행 → T3 완료 (시각 4)  switch 2
틱 [4,7)  T1 남은 3틱 실행 → T1 완료 (시각 7)           switch 3
```
시뮬레이션 문제는 이렇게 손으로 타임라인을 그려 검증하는 습관이 중요합니다.

## 체크 포인트
- 시각이 최대 10^9 이므로 **틱 단위 루프는 시간 초과**입니다.
  "다음 이벤트(다음 도착 시각 또는 현재 태스크 완료 시각) 중 빠른 쪽"으로 시간을 점프하세요.
- `priority_queue`에 `(우선순위, 도착시각, 번호)` 튜플을 넣으면 비교 규칙을 그대로 쓸 수 있습니다.
- 완료 시각은 최대 약 10^9 + 10^5 × 10^4 = 2×10^9 로 `int` 한계(약 2.1×10^9)에 매우 가깝습니다. 중간 계산까지 안전하게 `long long`을 쓰세요.
